# AbsoluteCinema

## Назначение

Учебное iOS-приложение для поиска фильмов, личных оценок и списка «Хочу посмотреть».
Разработчик имеет опыт программирования, но впервые работает со Swift и iOS.
Решения должны быть небольшими и понятными настолько, чтобы он мог объяснить их на занятии.

## Архитектура и технологии

- Swift, SwiftUI, Observation, SwiftData, UserDefaults; минимальная версия iOS — 17.
- MVVM: View показывает данные и передаёт действия; ViewModel хранит состояние экрана и выполняет его логику; слой данных обращается к хранению и API.
- Локальное состояние отображения, например фокус поля, может оставаться во View.
- Features содержит экраны и ViewModel; Models — структуры данных; Data — хранение и работу с данными; Shared — общие элементы интерфейса.
- Общие зависимости создаются при запуске приложения и передаются через инициализаторы.
- Добавляйте слой, протокол или стороннюю зависимость только для конкретной потребности проекта.
- Изменения объясняйте на одном пользовательском сценарии с указателями на соответствующий код.
- Личные записи хранятся в SwiftData, небольшие настройки — в UserDefaults; сведения о фильмах поступают из TMDB при подключении сети.
- Ключи и токены TMDB остаются в локальной конфигурации вне Git и вывода команд.

## Режим работы и проверки

- Вносите изменения в исходный код. Документацию и AGENTS.md меняйте только по прямому запросу пользователя.
- Самостоятельно не собирайте, не устанавливайте и не запускайте приложение, не запускайте тесты и не управляйте симулятором для проверок.
- Сборку, запуск и проверку SwiftData и UserDefaults выполняет пользователь. Проект — AbsoluteCinema.xcodeproj, доступная общая схема — AbsoluteCinemaCI.
- По прямому запросу пользователя 22 октября 2026 года выполнен прогон: сборка успешна, 9 unit-тестов и 1 UI-тест прошли, 1 UI-тест упал при замене текста черновика. Подробности и границы проверки — в CURRENT_AUDIT.md; это не постоянное разрешение на автоматические запуски.
- Тесты не добавляйте и не изменяйте до отдельного указания пользователя.
- Можно читать код, анализировать поток данных и просматривать diff без запуска приложения.
- В конце кратко сообщайте, что изменили и какие действия пользователю проверить, включая ожидаемый результат.
- Не выдавайте статический анализ за проверку работающего приложения.
- Эти правила заменяют прежние указания об автоматической сборке и ручной проверке агентом в документах проекта. Изменить режим может прямое указание пользователя.
